Studio includes a findings and analytics layer for security workflows.

That layer is what turns scanner output and workflow results into something you
can:

- search
- filter
- summarize
- visualize
- retain with policy

## Core Model

The public product uses ClickHouse for security findings and analytics queries.

Common flow:

1. a scanner or workflow step emits findings
2. an analytics sink or related pipeline indexes the result
3. the backend exposes query and metadata APIs
4. the frontend renders findings, dashboards, and settings around that data

## What Users See

Relevant product surfaces include:

- security dashboards
- scan result views
- findings tables and detail views
- analytics settings

## Retention

Retention is intentionally simple in OSS:

- public self-hosted Studio uses a single-tenant default ceiling
- the public API can still expose plan-shaped fields as nullable compatibility
  fields

## Self-Hosted vs ShipSec Cloud

In ShipSec Cloud, analytics retention is derived from the active billing plan.

In self-hosted Studio, the simpler single-tenant default remains the main
behavior to expect.

## Product Analytics vs Security Analytics

There are two different analytics concepts in the repo:

- **security/workflow analytics** for findings and execution results
- **product analytics** for frontend telemetry such as PostHog

This page is about the security/workflow side.
