title: "Secrets & API Keys"
description: "Manage runtime secrets and API keys without baking credentials into workflows"
---

Studio separates workflow logic from credential material.

That means workflows should reference:

- secrets
- API keys
- provider connections

instead of embedding raw credentials directly in graph definitions.

## Secrets

Secrets are the preferred place for sensitive runtime material such as:

- provider API keys
- tokens
- webhook secrets
- private connection details

## API Keys

API keys are useful for machine-to-machine access and controlled product access
patterns where a user session is not the right fit.

## Why This Separation Matters

Separating runtime credentials from workflow definitions makes it easier to:

- rotate secrets
- reuse workflows safely
- keep logs and artifacts clean
- audit operational changes
