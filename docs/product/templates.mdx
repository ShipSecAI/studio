Templates are one of the fastest ways to get value from Studio.

Today there are two important template surfaces:

- **workflow templates** for executable automations
- **report templates** for rendered output and presentation

## Workflow Templates

Workflow templates are prebuilt automations that can be instantiated into new
workflows.

They are useful for:

- code security scans
- cloud posture workflows
- attack-surface discovery
- AI-assisted review flows

In the public product, the main workflow template experience is the built-in
workflow template library exposed in the application.

## Report Templates

Report templates define how findings and results are rendered.

They support:

- built-in published templates
- organization-published templates
- draft and publish flows for iterative authoring

This lets teams standardize the presentation layer around recurring security
work.

## Template Publishing

There is also an optional Git-backed template publishing flow in the codebase.
That is useful when a deployment wants reviewable template submission and sync
behavior, but it is not the main story the public product should lead with.

The most important public story is:

- browsing and using built-in workflow templates
- working with report templates
- understanding how teams can standardize repeatable automation

## Why Templates Matter

Templates make Studio more than a blank canvas:

- operators get a faster starting point
- teams can standardize common patterns
- workflows stay reusable instead of copy-pasted
- reporting can match internal conventions
