Studio supports GCP as a first-class cloud integration surface.

Use it when you need:

- project or organization inventory
- graph-style cloud indexing
- workflow access to GCP APIs

## OSS Setup Path

The public product supports two self-managed GCP routes:

- service account JSON for the simplest community-edition setup
- impersonation for short-lived access without sharing customer keys

## Two Public GCP Routes

### Service Account JSON

Use this when you want the simplest self-hosted path:

- create a service account
- create a JSON key
- store that key as the Studio connection backend

### Impersonation

Use this when you want:

- no customer key JSON stored in Studio
- short-lived access tokens
- a cleaner least-privilege setup for larger environments

## What The Surface Covers

Current GCP-related product areas include:

- integration setup
- inventory and cloud-security workflows
- graph and analytics-oriented processing

## Recommended Pattern

As with AWS, keep the workflow graph focused on connection references and
runtime resolution rather than embedding provider credentials directly in the
graph definition.

## Self-Hosted vs ShipSec Cloud

ShipSec Cloud runs the same GCP capability in the hosted deployment.

In self-hosted Studio, the GCP model remains direct and self-managed.
