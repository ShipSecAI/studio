## Choose Your Path

ShipSec Studio has two public setup paths:

### 1. Use The Published Images In Your Own Deployment

Best for:

- self-hosting
- running Studio on your own infrastructure
- building your own runtime model around the published images

The public repo publishes the Studio application images. Pair them with the required backing services described in [Self-Hosting](/self-hosting).

### 2. Source Development

Best for:

- contributors
- source-level debugging
- local product development

```bash
git clone https://github.com/ShipSecAI/studio.git
cd studio
just init
just dev
```

This starts the Studio app processes from source. Runtime services must be provided separately by your local or deployment environment.

## Source Development

Requirements:

- Bun
- just
- access to the services your env files point at

Start:

```bash
just init
```

This installs dependencies and creates:

- `backend/.env`
- `worker/.env`
- `frontend/.env`

Start:

```bash
just dev
```

The public repo no longer ships the full local runtime overlay. `just dev` assumes your configured backing services already exist.

See [Development / Multi-Instance Dev](/development/multi-instance-dev) for contributor-oriented local instance details.

## Environment Basics

### Required Everywhere

- `SECRET_STORE_MASTER_KEY`

### Optional but Common

- `CHAT_AI_MODEL_ID`
- `CHAT_AI_BASE_URL`
- `CHAT_AI_API_KEY`

### Integration Configuration

Configure only what you actually plan to use:

- GitHub
- AWS
- GCP
- Slack
- Jira

The open-source model is direct configuration, not hosted indirection.

## Migration Behavior

`just dev` applies the committed migrations before starting the app services.
