## Choose Your Path

ShipSec Studio has two public setup paths:

### Docker Quickstart

Best for:

- local evaluation
- fastest self-hosted start
- not caring about source builds

```bash
git clone https://github.com/ShipSecAI/studio.git
cd studio
just quickstart
```

This uses the public quickstart stack and applies backend migrations automatically.

### Source Development

Best for:

- contributors
- source-level debugging
- local product development

```bash
git clone https://github.com/ShipSecAI/studio.git
cd studio
just init
just dev
```

This uses the shared infra + PM2 development flow.

## Docker Quickstart Details

Requirements:

- Docker Desktop or compatible Docker runtime
- enough local memory for the bundled services

Start:

```bash
just quickstart
```

Endpoints:

- App: `http://localhost:8080`
- API: `http://localhost:8080/api`
- Temporal UI: `http://localhost:8081`
- Redpanda Console: `http://localhost:8082`
- MinIO Console: `http://localhost:9001`

Authentication defaults:

- username: `admin`
- password: `admin`

AI is optional. If you want AI steps to work, export these before startup:

```bash
export CHAT_AI_BASE_URL="https://api.openai.com/v1"
export CHAT_AI_API_KEY="..."
export CHAT_AI_MODEL_ID="gpt-5.4-mini"
just quickstart
```

Stop or clean:

```bash
just quickstart stop
just quickstart clean
```

## Source Development Details

Requirements:

- Bun
- Docker
- just

Initialize:

```bash
just init
```

This installs dependencies and creates:

- `backend/.env`
- `worker/.env`
- `frontend/.env`

Start:

```bash
just dev
```

The dev flow:

- starts shared local infra
- validates env files
- runs migrations
- launches frontend, backend, and worker via PM2

See [MULTI-INSTANCE-DEV](/MULTI-INSTANCE-DEV) for contributor-oriented local instance details.

## Environment Basics

### Required Everywhere

- `SECRET_STORE_MASTER_KEY`

### Optional but Common

- `CHAT_AI_MODEL_ID`
- `CHAT_AI_BASE_URL`
- `CHAT_AI_API_KEY`

### Integration Configuration

Configure only what you actually plan to use:

- GitHub
- AWS
- GCP
- Slack
- Jira

The open-source model is direct configuration, not hosted indirection.

## Migration Behavior

### Docker Quickstart

You do **not** need a separate migration step.

The backend container runs migrations automatically on startup.

### Source Development

`just dev` applies the committed migrations before starting the app services.

## Notes on Older Local Setups

The public quickstart uses its own Compose project and volumes.

If you previously ran an older local setup:

- stop it first if ports conflict
- you do not need to manually “migrate” that older setup just to try the current public stack
