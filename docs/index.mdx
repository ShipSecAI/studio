ShipSec Studio is the open-source harness for **agent-native security workflow orchestration**.

It gives you one system for combining:

- workflow graphs
- AI agents
- MCP tools
- security scanners
- API calls
- human approvals
- observability and replay

## What Studio Actually Is

Studio is not just a workflow builder and not just an agent shell.

It is the runtime layer that lets security teams:

- design repeatable workflows
- attach tools and credentials safely at runtime
- run durable automations with retries and pause/resume behavior
- keep humans in the loop when decisions matter
- observe runs end-to-end through logs, terminal streams, events, artifacts, and audit records

## Why Teams Use It

- **Agent-native**: agents can operate inside real security workflows instead of isolated chats.
- **Durable**: workflows survive failures and long-running waits.
- **Governable**: approvals, scoping, credentials, and auditability are built into the execution model.
- **Composable**: mix AI, MCP, HTTP, cloud, GitHub, Jira, Slack, and scanner steps in one system.
- **Reusable**: start from templates, report templates, and component building blocks instead of hand-rolled glue.

## Open Source First

The public repository is designed for **self-hosted, usually single-tenant deployments**.

That means:

- you run the stack on your own infrastructure
- you configure your own providers and credentials
- you can use local auth or external auth
- you can connect AI models directly with base URL + API key

ShipSec Cloud is the managed hosted offering. It exists, but public docs focus on how to use Studio as a self-hosted product.
