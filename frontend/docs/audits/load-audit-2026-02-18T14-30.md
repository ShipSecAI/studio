## Bug Report

### 🐛 BUG-1 — Container Security tab shows Dependency data [MEDIUM]

**Severity:** Medium
**Location:** Security Dashboard → Container Security tab
**Description:** The Container Security view renders `package@version` asset keys and dependency-style titles (CVE IDs for packages), identical to the Dependency Security view. Expected scanners are `trivy-container` and `grype` with container image refs (e.g., `nginx:1.21`). Actual: 120 findings with dependency data.
**Impact:** Container security posture is not visible; container findings are invisible to users.
**Reproduction:** Navigate to `/dashboards/security?view=container-security`, observe `package@version` format in asset_key column.

---

### 🐛 BUG-2 — FindingDetailSheet does not close [MEDIUM]

**Severity:** Medium
**Location:** Security Dashboard → Any finding row → FindingDetailSheet
**Description:** Neither the Close (×) button nor the Escape key dismisses the FindingDetailSheet. The URL retains `?finding=<id>` after clicking Close. The TemplateDetailDialog (separate component) closes correctly, confirming the issue is specific to FindingDetailSheet.
**Impact:** Users are unable to dismiss the detail sheet without navigating away, degrading UX significantly.
**Reproduction:** Click any finding row to open the sheet; press Escape or click the × button — sheet remains open.

---

### 🐛 BUG-3 — "Use Template" does not navigate to workflow builder [MEDIUM]

**Severity:** Medium
**Location:** Templates page → "Use Template" button
**Description:** Clicking "Use Template" successfully creates the workflow (toast confirms creation, URL changes to `/workflows/<uuid>`), but the page remains on `/templates` instead of navigating to the WorkflowBuilder.
**Impact:** Users must manually find the new workflow in `/builder` after template instantiation, breaking the expected UX flow.
**Reproduction:** Click "Use Template" on any template card; observe URL change in address bar but page does not navigate.

---

### ℹ️ INFO-1 — Two API calls bypass nginx proxy [LOW]

**Description:** `GET http://localhost:3211/api/v1/components` and `GET http://localhost:3211/api/v1/schedules` use the direct backend port rather than the nginx proxy (`http://localhost/api/v1/...`).
**Impact:** Minor — in production these would not exist. No functional impact in dev.

---

### ℹ️ INFO-2 — Home page hides security stats without integrations [INFO]

**Description:** The home page shows the "onboarding" view (Getting Started checklist, What You'll Unlock) even when security findings exist in OpenSearch, because no integrations (GitHub/AWS) are connected. The `security.categoryCounts` query successfully returns data, but the Quick Stats Row, Findings Trend Chart, Needs Attention Card, and Recent Activity Feed are all conditionally hidden.
**Impact:** Intentional product decision, but worth validating — power users seeding data directly may find home page unhelpful.

---

### ℹ️ INFO-3 — Security Dashboard route mismatch with plan [INFO]

**Description:** The testing plan referenced `/security` as the security dashboard route; actual route is `/dashboards/security`.
**Action:** Update `.context/plans/private-branch-frontend-testing-plan.md` if reused.
